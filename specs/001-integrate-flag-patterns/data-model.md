# Data Model – Flag Patterns Strategy Integration

## Entity Overview

### FlagPatternsConfig
Schema describing tunable parameters consumed by `FlagPatternsStrategy`.

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| `min_pole_bars` | int | >= 3 | Minimum pole length for candidate patterns. |
| `max_flag_ratio` | float | 0 < r ≤ 0.6 | Maximum flag width / pole width ratio. |
| `hold_multiplier` | float | > 0 | Multiplier applied to flag width to determine holding period. |
| `use_trendline_mode` | bool | — | Toggle between PIP-based and trendline-based detection. |
| `order_scan_range` | List[int] | non-empty | Enum of order parameters passed to upstream detector. |
| `plot_theme` | str | one of [`dark`, `light`] | Styling used for telemetry chart snapshots. |
| `risk` | RiskPolicy | — | Nested structure described below. |

### RiskPolicy
Encapsulates strategy-specific guardrails enforced by `RiskManager`.

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| `per_trade_risk_pct` | float | 0 < value ≤ 0.05 | Fraction of equity risked per trade. |
| `max_concurrent_positions` | int | ≥ 1 | Hard cap on simultaneous trades. |
| `daily_loss_cap_pct` | float | 0 < value ≤ 0.1 | Drawdown threshold that halts trading. |
| `cooldown_minutes` | int | ≥ 0 | Pause duration before restarting after halt. |

### FlagSignal
Structured output generated by `FlagPatternsStrategy.generate_signal`.

| Field | Type | Notes |
|-------|------|-------|
| `timestamp` | datetime | Signal emission time (UTC). |
| `symbol` | str | Trading pair (e.g., `BTC/USDT`). |
| `side` | Literal[`LONG`, `SHORT`] | Direction inferred from pattern type. |
| `entry_price` | Decimal | Quote price at confirmation point. |
| `stop_price` | Decimal | Derived from support/resistance slope. |
| `target_price` | Decimal | Pole height projection or ATR multiple. |
| `confidence` | float | 0..1 score derived from pattern metrics. |
| `pattern_id` | str | Unique ID linking to artifact bundle. |
| `metadata` | dict | Extra context (flag width, pole height, slopes). |

### StrategyArtifact
Artifacts persisted for reproducibility.

| Field | Type | Notes |
|-------|------|-------|
| `run_id` | str | ULID or timestamp-based identifier. |
| `validation_type` | Literal[`excellence`,`permute`,`wf`,`wf_permute`] | Script executed. |
| `seed` | int | RNG seed passed to runner. |
| `dataset_hash` | str | SHA256 of input dataset. |
| `metrics_path` | Path | CSV/JSON summary stored under `artifacts/flag_patterns/`. |
| `plots` | List[Path] | PNG charts for telemetry and audit. |
| `permutation_stats` | Optional[dict] | p-values, z-scores for permutation runs. |

### PortfolioSnapshot (extended fields)
No schema change required; ensure snapshots include Flag Patterns exposure with unique strategy key (`flag_patterns`).

## Relationships
- `FlagPatternsConfig.risk` references `RiskPolicy` (embedded).
- Each `FlagSignal` references a `StrategyArtifact` via `pattern_id` to tie live decisions back to validation results.
- Artifact summaries feed into telemetry pipeline allowing `/strategy_config` command to surface parameters and latest metrics.

## Data Flow Summary
1. `DataSourceBase` fetches klines → normalized by helper utilities (log transform, numpy array).
2. Upstream TAA functions return `FlagPattern` dataclass objects → mapped to `FlagSignal` records.
3. RiskManager consumes `FlagSignal` + `FlagPatternsConfig.risk` to size positions and enforce caps.
4. Validation runners persist `StrategyArtifact` bundles; metadata stored in JSON for reproducibility.
5. Telemetry uses artifact metadata + `FlagSignal.metadata` to render chart snapshots and status updates.
